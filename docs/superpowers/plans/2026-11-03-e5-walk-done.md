# E5 Walk done by hand or by steps — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Today's walk row can be ticked by hand, and shows done once today's steps reach the step goal.

**Architecture:** Same pattern as reading ticked by hand (Plan decision 55). A hand tick logs a 20-min `walk` session tagged `routineKey: 'by-hand'`, with no schema change. Steps-done is computed from `todayStepsProvider` and `stepGoalProvider`, and nothing is logged.

**Tech Stack:** Flutter, Riverpod 3, drift.

**Spec:** [docs/superpowers/specs/2026-11-03-e5-e7-walk-move-week-design.md](../specs/2026-11-03-e5-e7-walk-move-week-design.md) §4

- Version 1.9.0+11 (`pubspec.yaml` and `appVersion` in `backup_service.dart`); PR title `feat(today): tick the walk by hand or by steps`.

## Review Focus

- Steps exactly at the goal (6,000 of 6,000): done.
- Steps null (no Health access): row behaves as before, plus the tick.
- A timed walk today and no hand walk: done, circle not tappable (no accidental removal of a real walk).
- Hand tick, then steps reach the goal: untick removes the hand walk; row stays done.
- Coming back to the app after walking: steps re-read on resume.
